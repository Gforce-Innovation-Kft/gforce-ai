# Governance v2 — design

Approved by Gabor 2026-08-14 (second interview session, follows
[`docs/intent/industry-upstream-flow.md`](../intent/industry-upstream-flow.md)).
Everything ratified in v1 — catalog-of-record, delta-not-fork overrides, the
ratification PR as human trust boundary, industry → fleet → shared → local
precedence — is unchanged. This spec covers only the delta on top of `main`
(`3d19948`).

## Decisions

| Question | Ruling |
|---|---|
| Agent namespace | `gforce-` slug prefix on every GForce-owned agent; validator-enforced |
| GForce skill namespace | Same prefix; `salesforce-developer` → `gforce-salesforce-developer` via the normal bump path |
| Override representation | Metadata + literal tripwires, hardened with a JSON Schema and multiple tripwire variants — not patch-based, not region-hashed |
| Local vs security rules | Local wins everywhere except a short marked non-overridable core; exceptions require a `gforce-ai` PR |
| Agent provenance | New `gforce-manifest.json` per consumer; `skills-lock.json` stays untouched (owned by the skills CLI) |
| CI token budget | CI is static-only (formatting, sections, templates, schemas, naming, version bumps) — zero LLM tokens. LLM evals run only on explicit dispatch; CI checks scorecard *presence*, never generates one |
| Versioning | Per-skill/per-agent semver in frontmatter with an enforced bump-on-change; repo-level semver tags with generated release notes |

## Architecture

```
INDUSTRY        forcedotcom/sf-skills · trailofbits · sickn33 · github/awesome-copilot
   │            (installed direct from upstream, hash-pinned in skills-lock.json)
   ▼
FLEET           gforce-ai: catalog-of-record, deltas/overrides, standards, agents
   │            (never mirrors upstream bytes; ratifies pins; owns the trust boundary)
   ▼
SHARED          capability-marker installed skills + gforce-* agents per consumer
   │            (provenance in gforce-manifest.json)
   ▼
LOCAL           .claude/references/local-standards.md — read last, wins
                (except the non-overridable core)

Update flow:
  upstream ──weekly──▶ compare vs ratified pin ──▶ override conflict scan
      ──▶ ratification PR (human review, never auto-merged) ──▶ new pin
      ──▶ consumer bump PRs (poll default / actions:write dispatch urgent)
      ──▶ verify-pins in the bump PR ──▶ merge ──▶ SessionStart reports OK
```

## Components

### 1. Naming standard + validator

- Agent `name:` must match `^gforce-[a-z0-9-]+$` and equal the filename stem.
  Rename: `gforce-sf-code-reviewer`, `gforce-gha-workflow-author`,
  `gforce-skills-auditor`. Sweep references in fleet docs and consumers.
- GForce-owned skills use the same namespace. `gforce-github-actions` already
  complies; `salesforce-developer` is renamed in a scheduled consumer bump.
- `scripts/validate-naming.sh`: slug pattern, filename match, explicit `tools:`
  list, `model:` present, description contains both `TRIGGER when:` and
  `DO NOT TRIGGER when:`, body ≤ 200 lines. Upstream-installed content never
  lives in this repo, so it is exempt by construction.

### 2. Override schema

`schemas/overrides.schema.json` validated in CI against every
`skills/*/overrides.json`:

```json
{
  "source": "forcedotcom/sf-skills",
  "overrides": [
    {
      "upstream_paths": ["skills/platform-soql-query"],
      "tripwires": ["WITH SECURITY_ENFORCED", "SECURITY_ENFORCED"],
      "gforce_rule": "WITH USER_MODE — enforces CRUD and sharing as well as FLS",
      "reason": "USER_MODE supersedes SECURITY_ENFORCED for FLS + sharing"
    }
  ]
}
```

`tripwires` (plural, ≥ 1) replaces the single-string field — closes the
rewording gap where an upstream reflow degrades CONFLICT to TOUCHED. The
ratification script loops all variants. A CI check errors when an
`upstream_paths` prefix no longer exists at the ratified commit (a dead anchor
silently disables detection).

### 3. Non-overridable core

`standards/invariants.md` — the full invariant list (see below) with a marked
non-overridable subset. Local standards win on everything else; an exception to
the core requires a `gforce-ai` PR, not a local edit. Fleet skills reference
this file instead of restating it.

### 4. Agent provenance — `gforce-manifest.json`

Per consumer, generated by `scripts/gen-manifest.sh` at install/bump time,
never hand-edited:

```json
{
  "gforce_ai_commit": "<sha>",
  "gforce_ai_release": "v2.0.0",
  "agents": { "gforce-sf-code-reviewer": "sha256:…" },
  "generated_at": "2026-08-14"
}
```

Gives agents the hash-pinned provenance skills already have via
`skills-lock.json`. The two files never overlap: the lockfile is the skills
CLI's, the manifest is ours.

### 5. Consumer convergence + pin verifier

- `.github/workflows/reusable-governance-bump.yml` (`workflow_call`): weekly
  poll compares the consumer's manifest + lockfile against ratified state; when
  behind → dedicated branch, `npx skills update` (mechanized where it is safe —
  the rewrite-in-place trap never touches a shared branch), regenerate
  manifest, open a PR. Urgent path stays `actions:write` dispatch — never
  `contents:write`.
- `scripts/verify-pins.sh`: recomputes installed-bytes hashes against the
  ratified upstream commit (the manual PIN-MATCH check, automated). Runs in
  every bump PR and on demand locally.

### 6. SessionStart report — read-only

Hook script shipped to consumers. Local checks only (manifest vs installed
agent hashes vs lockfile) plus a ≤ 2 s fail-soft fetch of the raw catalog for
staleness (offline → reported as `offline`, never an error). One line when
clean:

```
GForce governance: OK — industry ba78d38 → fleet v2.0.0 → shared ✓ → local active
```

Expanded detail only on `DRIFT`. Never writes, never blocks the session.

### 7. CI validation — zero LLM tokens

`.github/workflows/validate.yml` on every PR, static checks only:

| Check | Tool |
|---|---|
| Agent/skill frontmatter fields + sections vs templates | bash + awk |
| Naming rules (component 1) | `validate-naming.sh` |
| `catalog.json` + `overrides.json` vs JSON Schemas | node + ajv (devDependency) |
| Dead override anchors (path prefix gone upstream) | git ls-tree at ratified pin |
| Version bump present when skill/agent content changed | git diff vs main |
| Scorecard freshness: PR touching `agents/**` carries a scorecard in `standards/evals/` matching the agent's current content hash | jq + sha256 |

LLM evals (`evals/run-suite.ts`, existing, cost-capped) run **only** via
`workflow_dispatch` or locally — burning tokens is always an explicit human
decision. CI verifies the *result* exists and is current; it never generates
one. The existing "advisory first, required later" phase-in applies to the
scorecard-freshness check, not to running models in CI.

### 8. Versioning & releasing

- **Per-skill and per-agent semver** in frontmatter (`version:`). CI fails a
  PR that changes content without bumping (static diff check).
- **Repo releases:** semver tags `vX.Y.Z`.
  - **major** — breaking governance change: precedence semantics, the
    non-overridable core, renames requiring consumer migration.
  - **minor** — new or changed skills, agents, standards, catalog
    ratifications.
  - **patch** — docs and fixes.
- `release.yml` on tag push: GitHub Release with notes generated from
  conventional commits (already the fleet standard). No artifacts — consumers
  pin commits via lockfile/manifest; the tag is the human-readable marker the
  bump PR references.

### 9. Catalog extension + branch protection

- Add `trailofbits/skills`, `sickn33/antigravity-awesome-skills`,
  `github/awesome-copilot` rows to `upstream/catalog.json` with ratified pins.
  The ratification script already iterates sources — data change, not code.
  Closes the hole where `docker-expert` relabeled itself `risk: critical` with
  zero review.
- Branch protection on `main`: PR + review required — "never auto-merge"
  becomes mechanism, not policy.

## Templates

`templates/agent-template.md` and `templates/skill-template.md` — canonical
frontmatter + required sections. The section validator checks against these,
so the template and the check cannot drift apart.

## Testing

| Case | Expected |
|---|---|
| Upstream unchanged since pin | `UNCHANGED` |
| Upstream touched an anchored path, no tripwire hit | `TOUCHED` |
| Tripwire text present in diff hunks | `CONFLICT` |
| Agent named without `gforce-` prefix | validator FAIL |
| Correctly named agent | validator PASS |
| Consumer manifest matches installed hashes + pins | report `OK` |
| Edited agent copy / stale pin | report `DRIFT` |
| Skill content changed, version not bumped | CI FAIL |
| Clean eval fixture | no false positive (existing suite) |
| Defect fixture | defect detected (existing suite) |

Ratification verdicts are tested against synthetic git fixture repos (no
network, no live upstream dependency in tests).

## Migration

1. Land schemas, validators, templates, `validate.yml`, invariants doc (no
   renames yet — CI goes green on current content with naming as warning).
2. Rename agents + `salesforce-developer`; regenerate manifests; sweep
   consumer references; flip naming to blocking. Tag `v2.0.0` (breaking:
   renames).
3. Extend catalog to the three remaining sources (one ratification PR each).
4. Roll out bump workflow + SessionStart hook to consumers, one PR per repo,
   `sf-docker-images` first (already the pilot).

## Invariants (`standards/invariants.md`)

Non-overridable core marked ●:

1. ● Upstream content is never modified in place, mirrored, or forked.
2. ● Every upstream dependency is pinned (lockfile hash + ratified catalog pin).
3. ● Upstream changes touching an override require central human review; the
   ratification PR is never auto-merged.
4. ● No personal access tokens anywhere in the fleet — scoped GitHub App
   tokens only.
5. ● Consumer agent copies are read-only; changes land in `gforce-ai` first.
6. ● `npx skills check`/`update` run only on dedicated branches.
7. ● Governance checks are read-only outside a controlled update PR.
8. GForce overrides are deltas with machine-readable provenance, never
   restatements.
9. Every GForce-owned agent and skill carries the `gforce-` namespace.
10. Consumers converge only from a ratified state.
11. Agent changes carry a current eval scorecard before release; running evals
    is always an explicit human decision, never an ambient CI cost.
12. Local standards are the final extension point and win on everything
    outside the core.

## Out of scope

- Re-hosting upstream bytes, MCP for static docs, repo renames (unchanged
  from v1 intent).
- LLM-based conflict analysis — deterministic detection + human review is the
  chosen sophistication level.
- Eval runs in per-PR CI — token spend stays opt-in.
